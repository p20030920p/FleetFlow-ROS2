Five AGVs move cans between carding, drawing and roving machines on a 26 × 16 m floor.
A scheduler assigns the work, each vehicle plans and drives its own route, and a shift board
reports the floor.

## Quick start

```bash
mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src
git clone https://github.com/p20030920p/FleetFlow-ROS2.git
cd ~/ros2_ws && colcon build --symlink-install && source install/setup.bash

ros2 launch fleetflow_sim factory.launch.py                    # Gazebo, headless
ros2 launch fleetflow_sim factory.launch.py headless:=false gui:=true
ros2 launch fleetflow_sim logic_only.launch.py num_robots:=8 policy:=ssi   # no Gazebo
```

Camera topics are **not bridged by default**: a bridged `sensor_msgs/Image` whose subscriber
falls behind grows without bound (measured at ~5 GB RSS, enough to trigger the OOM killer).
Cameras are `always_on=0` — they render only while subscribed — and are bridged one at a time:

```bash
ros2 launch fleetflow_sim factory.launch.py bridge_cameras:=true
ros2 run ros_gz_bridge parameter_bridge "/view_iso/image@sensor_msgs/msg/Image@gz.msgs.Image" &
python3 tools/capture_views.py /tmp/shots /view_iso/image && kill %1
```

## What runs

<p align="center">
  <img src="./assets/readme/architecture.png" width="100%" alt="Runtime topology">
</p>

| Concern | Implementation |
| --- | --- |
| **Namespaces / TF** | One namespace and one `robot_state_publisher` per vehicle, so TF is a forest of disjoint trees rather than one contested chain. |
| **QoS per data class** | Best-effort shallow queues for scan and odometry; reliable deeper queues for commands, tasks and fleet state. |
| **Docking** | Lease-based. A vehicle holds at most one lease, never holds one while requesting another, and waits on open floor — which removes *hold-and-wait*, so no circular wait can form. Leases carry a TTL and are reclaimed. |
| **Multi-slot docking** | Storage areas expose a ring of dock slots instead of one shared point; otherwise every vehicle converges, avoidance deadlocks and the watchdog aborts the task. |
| **Avoidance** | Reciprocal yielding (slow in a look-ahead cone, stop for a higher-priority peer, hard stop at the safety radius), deterministic priorities to break standoffs, peers injected as a dynamic obstacle layer before each A\* call, and an independent LiDAR stop. |
| **Energy and recovery** | Drain per metre; below a threshold a vehicle stops bidding, queues for a charger through the same lease mechanism, and rejoins. A stalled vehicle re-plans then abandons; the scheduler reclaims tasks from silent vehicles. |
| **Pull allocation** | Vehicles ask for work only when idle, which removes the double-assignment race a push model has. |

## Allocation

Assigning transport work to vehicles is **multi-robot task allocation**. The textbook cost is
deadhead distance, `c(r,t) = ‖p_r − s_t‖₂`. That is wrong for a spinning mill in three ways: a
machine has exactly **one** docking position, battery is a **hard** constraint, and the cheapest
vehicle now is not the cheapest fleet over a shift.

| Policy | Rule | Information |
| --- | --- | --- |
| `random` | random pending task | none — lower bound |
| `nearest` | own nearest task | local only |
| `ssi` | sequential single-item auction over deadhead distance | global poses + tasks |
| **`ca_ssi`** | **the same auction over a six-term industrial cost** | **+ contention, energy, load, age** |
| `hungarian` | linear-assignment optimum of that cost matrix | global, one-shot |

`ca_ssi` keeps the auction **unchanged** — only the cost function differs, so the comparison
isolates the cost model rather than the algorithm class.

<p align="center">
  <img src="./assets/readme/cost-model.png" width="100%" alt="The six terms of the CA-SSI cost function and their weights">
</p>

```
J(r,t) = α·‖p_r − s_t‖                    ① deadhead
       + β·‖s_t − g_t‖                    ② laden travel
       + γ·(n_src + 1.5·n_dst)            ③ dock contention
       + δ·max(0, e_need + reserve − e_r) ④ energy feasibility
       + η·(d_r − d̄)/d_max                ⑤ load balance
       − ζ·min(age, 20)                   ⑥ task ageing      (+ 0.02·priority)
```

Weights are in **equivalent metres**, so they are readable: avoiding one contended dock costs
the same as `γ/α = 6 m` of driving. The dropoff is weighted 1.5× because a vehicle that cannot
unload blocks the aisle. Ageing is capped — uncapped it dominates every other term and the
auction degenerates to FIFO.

## Results

5 policies × 3 seeds × 120 s, 80 units in circulation, identical plant; only the fleet differs.

<p align="center">
  <img src="./assets/readme/policy-comparison.png" width="100%" alt="Throughput, latency, travel per task and utilisation for five policies at two fleet sizes">
</p>

| Policy | 3 AGVs: tasks/min | 3 AGVs: m/task | 8 AGVs: tasks/min | 8 AGVs: m/task | 8 AGVs: near-miss |
| --- | ---: | ---: | ---: | ---: | ---: |
| random | 9.0 | 12.2 | 10.6 | 13.8 | 6.7 |
| nearest | 10.4 | 9.8 | 12.3 | 11.7 | 4.3 |
| ssi | 10.0 | 10.1 | 15.2 | 12.9 | 6.3 |
| **ca_ssi** | **10.7** | **9.1** | **18.7** | **10.8** | **3.0** |
| hungarian | 9.9 | 10.4 | 14.9 | 11.9 | 6.5 |

**Before → after** (same code, only `ca_ssi_cost` changed):

| Metric | Fleet | SSI | CA-SSI | Change | vs `random` |
| --- | --- | ---: | ---: | ---: | ---: |
| Throughput | 3 AGVs | 10.0 | 10.7 | **+7 %** | +18 % |
| Throughput | 8 AGVs | 15.2 | 18.7 | **+23 %** | +77 % |
| Travel per task | 3 AGVs | 10.1 | 9.1 | **−10 %** | −25 % |
| Travel per task | 8 AGVs | 12.9 | 10.8 | **−16 %** | −22 % |
| Near-miss events | 8 AGVs | 6.3 | 3.0 | **−53 %** | −55 % |

- **The edge grows with contention.** Three vehicles rarely want the same single-berth station;
  eight do it constantly, and there the same term is worth +23 % throughput and half the
  near-misses. `ca_ssi` is the only policy that can see the contention it is about to create.
- **`nearest` is not reliably better than `random`** — it answers whoever asks first, so a
  vehicle can claim a task a much closer peer was about to take.
- **`hungarian` is the single-round optimum and never wins.** It optimises a static matrix and
  cannot see contention, energy or queueing. An optimal assignment is not an optimal system.
- **The result is load-dependent.** With only 28 units in circulation the plant is WIP-starved,
  every policy converges to ≈16 tasks/min, and the choice of rule is not measurable at all.
  A policy study without its load condition is not reproducible.

## Ablation

Each of the six terms removed on its own; same auction, same seeds, same plant.

<p align="center">
  <img src="./assets/readme/ablation.png" width="100%" alt="Leave-one-out ablation of the CA-SSI cost terms">
</p>

| Cost model | tasks/min | vs full | m/task | latency (s) |
| --- | ---: | ---: | ---: | ---: |
| **CA-SSI (all six)** | **17.45** | — | **11.3** | **17.6** |
| − dock contention (γ) | 13.92 | **−20 %** | 12.6 | 18.6 |
| − energy feasibility (δ) | 14.63 | **−16 %** | 12.3 | 18.0 |
| − load balance (η) | 17.29 | −1 % | 11.6 | 18.0 |
| − task ageing (ζ) | 17.32 | −1 % | 10.9 | 17.0 |

Two terms carry the model: contention is worth a fifth of throughput, energy feasibility 16 %
(even at 0.10 %/m drain, because a vehicle that accepts a task it cannot finish must break off
and charge). Load balance and ageing are **honest nulls on this workload** — 120 s is too short
to build an odometer advantage, and an anti-starvation term bounds the worst case rather than
raising the average. Both are kept; neither is claimed to pay for itself here.

## Stability

From a Gazebo run with 4 AGVs over 200 s of wall clock: **35 tasks dispatched, 5 delivered,
0 errors, 0 watchdog aborts, 0 "no path", free memory never below 6.9 GB.** Under software
rendering Gazebo runs about five times slower than real time, which is why the timing study uses
`logic_only.launch.py` — same coordination stack, wall-clock accurate.

## Outlook

1. **The expensive part of a fleet is idle machines, not motion.** Every term prices *the
   mill's* cost, not the vehicle's: contention is weighted 6× deadhead distance because 6 m of
   extra driving is cheap and one stopped carding machine is not.
2. **The mechanism is fixed; domain knowledge enters through the cost.** A new constraint — a
   beam that must travel upright, a single-lane corridor at shift change — is a term, not a
   rewrite. A process engineer can read the weights without reading the code.
3. **Congestion-awareness transfers.** Every domain with single-berth resources — ports, wafer
   fabs, hospital logistics, gates — has this structure, and this harness measures it there too.
4. **Safety margin compounds.** Contention in the objective rather than in a recovery policy
   means fewer convergences, fewer standoffs, less watchdog intervention and a tighter safety
   radius. The near-miss column is the first hint of that loop, not its limit.
5. **Everything here is falsifiable.** Every number comes from a CSV in `experiments/`, produced
   by one command with fixed seeds. Replace `ca_ssi` and rerun.

## Notes and limits

- Pull-based dispatch is deliberate: a push model must track every vehicle's busy state, and a
  lost completion message leaves a vehicle permanently busy — the bug that motivated this design.
- `ca_ssi` prices the contention it can see, not the contention its next assignment will cause,
  and it assigns one task at a time rather than a route of several. Sequencing over a rolling
  horizon is the next step.
- `logic_only.launch.py` integrates odometry locally; the coordination logic is identical.
- Battery parameters are tuned so a charging cycle fits inside a short run — a behaviour
  demonstration, not an energy study.
